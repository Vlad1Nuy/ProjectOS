# Project OS V2

Локальное однопользовательское пространство для проектов, задач, памяти и контекста для обычного ChatGPT.

**Думать → планировать → выполнять → проверять → фиксировать → продолжать.**

## Достоверность состояния и границы этой реализации

- **FACT:** этот репозиторий создан на основе доступного стартового шаблона Next.js/PostgreSQL. Исходники установленной у пользователя V1 не предоставлялись.
- **FACT:** здесь реализованы проекты, задачи, Memory, AI Context, история, JSON/ZIP-экспорт, восстановление V2 и Windows-launcher.
- **ASSUMPTION:** интерфейс использует английские названия разделов, как в описании V1; инструкция и диагностика установки подробно объяснены ниже.
- **НЕ ПРОВЕРЕНО:** перенос реальных данных V1 и запуск `.cmd`/PowerShell на Windows. Успешная Linux-проверка не заменяет Windows acceptance test.
- Не направляйте эту версию на существующую БД V1 до сравнения схем и форматов. Создайте отдельную БД. Для дальнейшей интеграции нужны конкретные файлы V1, а не ZIP целиком.

## Архитектура

Next.js App Router + React + TypeScript; PostgreSQL через Drizzle; Zod для серверной валидации. Нет обязательного OpenAI API, облачного аккаунта, Docker или отдельного агента.

```text
src/app/page.tsx                 точка входа
src/app/globals.css              адаптивный интерфейс
src/app/api/workspace/route.ts   чтение и атомарное обновление workspace
src/app/api/health/route.ts      подключение к БД / наличие схемы
src/app/api/backups/route.ts     последняя копия перед восстановлением
src/components/                 интерфейс, редакторы, панели
src/lib/workspace.ts            типы, валидация, генерация Markdown, примеры
src/db/index.ts                 пул PostgreSQL, только DATABASE_URL
src/db/schema.ts                таблицы Drizzle
scripts/launcher.mjs            setup / check / normal / dev
scripts/start-project-os.cmd    Windows-точка входа
scripts/create-shortcut.ps1     создание ярлыка
.vscode/                       рекомендованные расширения и задачи
```

`project_os_workspaces` содержит один JSONB workspace и числовую ревизию. Обновление блокирует строку в транзакции, проверяет ревизию и увеличивает её. Устаревший запрос получает HTTP 409, а не молча перезаписывает новую версию. История генерируется сервером при изменении данных. Перед восстановлением прежнее состояние сохраняется в `project_os_backups` в той же транзакции.

Такое хранение выбрано для простого локального однопользовательского приложения; это не многопользовательская система совместного редактирования.

## Требования

- Windows 10/11 для ярлыка; веб-приложение также может работать в Linux/macOS.
- Node.js **22 LTS или новее** и npm: https://nodejs.org
- PostgreSQL 14+; работающая служба PostgreSQL.
- Браузер: актуальный Edge, Chrome или Firefox.
- Интернет для первоначальной установки зависимостей и, при желании, обычного ChatGPT. Ежедневная работа с workspace не требует внешнего API.
- VS Code и Git — для разработки, не для повседневного использования.

## Установка и первый запуск

### 1. Подготовьте отдельную папку

Распакуйте/клонируйте **этот** репозиторий. Не заменяйте неизвестную V1 без резервной копии. Можно выбрать любой путь, в том числе с пробелами.

### 2. Настройте PostgreSQL

Откройте pgAdmin, подключитесь к локальному серверу. Создайте отдельную роль с правом входа, задайте ей собственный пароль и создайте базу `project_os`, владельцем которой будет эта роль. Роль не должна быть суперпользователем. При отсутствии pgAdmin используйте SQL Shell (psql); пароль задавайте интерактивно командой `\password`, не вставляйте реальный пароль в Git или историю общих команд.

Служба PostgreSQL запускается через **Win + R → services.msc → PostgreSQL → Запустить**. Launcher проверяет соединение, но не устанавливает PostgreSQL и не запускает системные службы с правами администратора.

### 3. Создайте `.env`

В папке проекта скопируйте `.env.example`, назовите копию `.env`. Замените placeholders своим пользователем, паролем и именем БД. Включите показ расширений файлов Windows: файл не должен называться `.env.txt`.

`DATABASE_URL` имеет структуру `postgresql://USER:PASSWORD@HOST:PORT/DATABASE`. Настоящих паролей в репозитории нет. Символы `@`, `:`, `#`, `/` и другие специальные символы пароля должны быть URL-кодированы. Не публикуйте `.env`, скриншот строки подключения или содержимое БД.

`PORT=3000` задаёт порт launcher; допускаются целые значения 1024–65535. Для этой реализации используйте один `.env`; не создавайте противоречащие `.env.local`/`.env.production`.

### 4. Откройте терминал в папке проекта

В VS Code: **File → Open Folder → папка Project OS**, затем **Terminal → New Terminal**.

Запустите один раз:

```powershell
.\scripts\start-project-os.cmd --setup
```

Setup устанавливает зафиксированные зависимости через `npm ci`, проверяет БД, применяет схему Drizzle и собирает приложение. Он может занять несколько минут. Если `.env` отсутствует, создаётся шаблон и выводится просьба заполнить его; продолжения со случайными credentials нет.

**Важно:** `--setup` явно меняет схему выбранной БД. Для обновления сначала сделайте backup. Просмотрите предлагаемые изменения Drizzle, если команда запрашивает подтверждение. Не подтверждайте удаление существующих данных без анализа.

### 5. Проверьте окружение

```powershell
.\scripts\start-project-os.cmd --check
```

Ожидаемый результат: Node и зависимости доступны, PostgreSQL connection: OK, Database schema: OK.

### 6. Запустите приложение

```powershell
.\scripts\start-project-os.cmd
```

Браузер автоматически откроется после успешного healthcheck. При первом открытии пустой БД создаётся **пример workspace**, а не фиктивное состояние вашей V1. Очистить примеры можно в Settings; очищается весь текущий workspace с автоматической предварительной копией, поэтому сначала экспортируйте добавленную вами работу.

## Запуск через Windows-ярлык

Самый простой вариант, без изменения PowerShell Execution Policy:

1. Откройте каталог `scripts` в Проводнике.
2. Нажмите правой кнопкой на `start-project-os.cmd`.
3. **Показать дополнительные параметры → Отправить → Рабочий стол (создать ярлык)**.
4. Переименуйте ярлык в **Project OS**.
5. Дважды кликните. Окно launcher проверит окружение, запустит сервер и откроет браузер.

Альтернатива: правой кнопкой по `scripts/create-shortcut.ps1` → **Выполнить с помощью PowerShell**, если локальная политика разрешает. Скрипт не требует менять политику безопасности и спросит перед перезаписью ярлыка. При запрете PowerShell используйте способ выше.

После переноса папки создайте ярлык заново. В скриптах нет абсолютного пути или имени пользователя Windows; сам `.lnk` содержит путь на конкретном компьютере, как любой Windows-ярлык.

### Предсказуемое поведение

| Ситуация | Результат |
| --- | --- |
| Первый обычный запуск без сборки | Понятная инструкция выполнить `--setup` |
| Сервер этой папки уже работает | Открывается существующий workspace; второй сервер не создаётся |
| Другой сервер занял порт | Сообщение с номером порта; чужой процесс не завершается |
| Два ярлыка нажаты почти одновременно | Файл блокировки, ожидание готовности первого процесса |
| Нет Node.js | Ссылка на установку; окно остаётся открытым |
| Нет зависимостей | Инструкция выполнить `--setup` / `npm ci` |
| Нет `.env` / неверный URL | Понятная диагностика без печати credentials |
| PostgreSQL недоступен | Инструкция запустить службу и проверить настройки |
| Схема отсутствует | Инструкция выполнить setup после backup |
| Браузер закрыт | Сервер продолжает работать; открыть его можно повторным кликом |
| Нужно остановить | Вернуться в окно launcher и нажать **Ctrl+C** |
| Окно launcher принудительно закрыто | При следующем запуске проверяется действующий сервер и устаревшая блокировка; рекомендуемый способ остановки — Ctrl+C |

Launcher определяет свой экземпляр по хешу пути папки, а не только по номеру порта. После изменения `.env` остановите работающий сервер и запустите его заново.

## Запуск через терминал

Без Windows-обёртки (после setup):

```bash
node scripts/launcher.mjs
```

Диагностика:

```bash
node scripts/launcher.mjs --check
```

Ручная сборка:

```bash
npm run build
```

Ручной production-запуск с локальной привязкой:

```bash
npm run start -- --hostname 127.0.0.1
```

Если используете не launcher, учитывайте `PORT` самостоятельно. Обычный `npm run start` без hostname может слушать сетевые интерфейсы — для локального использования запускайте команду выше.

## Development mode

Для разработки и горячего обновления:

```powershell
.\scripts\start-project-os.cmd --dev
```

Или:

```bash
npm run dev -- --hostname 127.0.0.1
```

Остановить: Ctrl+C. Не запускайте dev и normal одновременно в одной папке; у них общая `.next`. После разработки перед normal выполните `npm run build` или `--setup`. В обычном режиме сборка не повторяется при каждом двойном клике — это быстрее и легче для слабого компьютера.

Выполняйте по очереди из корня проекта:

```bash

```

```

```

Для повторяемого браузерного smoke test запустите **отдельную тестовую БД и тестовый сервер**, затем:

## Git

`.gitignore` исключает node_modules, .next, .env, .env.*, логи, ключи, временные файлы, отчёты тестов и локальные backup-каталоги. `.env.example` содержит только placeholders. `package-lock.json` следует коммитить.

Простой цикл:

**Изменение → проверка → git status → git diff → commit**

```bash
git status
```

```bash
git diff
```

В VS Code выберите конкретные проверенные файлы, нажмите **Stage Changes**, введите осмысленное описание и нажмите **Commit**. Не добавляйте вслепую все файлы, если ещё не проверили наличие секретов. Перед первым commit при необходимости выполните `git init` и настройте имя/почту Git.

В терминале можно добавить конкретный файл командой `git add путь/к/файлу`, затем:

```bash
git commit -m "Improve local launch checks"
```

Если секрет когда-либо уже попадал в Git, `.gitignore` не удалит его из истории. Смените пароль/токен и отдельно очистите историю. Git сохраняет код, **не PostgreSQL workspace**. Для данных используйте экспорт.

## Проекты

Projects → New project. Укажите название, описание, цель, категорию, цвет, статус и этап. Нажатие названия карточки открывает детали; кнопки Tasks и Memory открывают соответствующие данные проекта. Archive сохраняет данные и скрывает проект из активных списков. В фильтре Archived его можно открыть и вернуть статус Active.

Статистика и прогресс рассчитываются из задач в БД. CANCELLED не входит в знаменатель прогресса. Архивные задачи исключены из рабочего списка «All active projects», но доступны через выбор архивного проекта.

## Задачи

Поддерживаются BACKLOG, READY, IN PROGRESS, BLOCKED, REVIEW, DONE, CANCELLED. У задачи есть описание, проект, приоритет, критерий завершения, зависимости и дата создания.

Чекбокс строки открывает **подтверждение DONE**, а не молча завершает задачу. Для DONE необходимо заполнить критерий и подтвердить фактическую проверку результата. Зависимости должны существовать, принадлежать тому же проекту, не образовывать цикл и быть завершены перед DONE. Сервер повторно проверяет эти условия. Удалить задачу, на которую ссылаются другие задачи, нельзя: сначала измените зависимости.

В двух вкладках используется контроль ревизии. При HTTP 409 скопируйте несохранённый текст в безопасное место, перезагрузите вкладку и повторите изменение. Автоматического опасного merge нет.

## Memory и источник истины

- `PROJECT.md` — живое название, описание, цель, статус и этап + редактируемые заметки.
- `TASKS.md` — генерируется из актуальных задач, отдельно не редактируется.
- `DECISIONS.md` — решения и основания.
- `RISKS.md` — риски и меры.
- `CHANGELOG.md` — генерируется из журнала, отдельно не редактируется.
- `MASTER_PROMPT.md` — правила общения и работы с проектом.
- `README.md` — инструкции и полезные ссылки по проекту.

Markdown хранится **в PostgreSQL**, а не синхронизируется с произвольными локальными `.md` файлами. ZIP-экспорт создаёт файловый снимок. Редактирование экспортированного файла не обновляет БД. Для `PROJECT.md` кнопка Full file показывает метаданные + заметки; в режиме Edit notes изменяются только заметки. Нажимайте Save changes. Несохранённые изменения отмечены точкой, уход со страницы требует подтверждения.

История хранит последние 1000 событий; в контекст CHANGELOG.md входят последние 30 релевантных событий. Это рабочая история, не бесконечный аудит.

## AI Context

Выберите проект и нужные файлы, напишите текущий запрос. Preview показывает точный текст; число токенов — приблизительная оценка, не API-токенизатор. Нажмите Copy context, затем Open ChatGPT и вставьте текст. Никакие данные автоматически не отправляются во внешнюю модель.

Перед отправкой проверьте контекст на секреты. Ответ ChatGPT сначала проверяется человеком; только затем обновляются Memory и задачи. В незащищённом браузерном контексте clipboard может быть недоступен — можно выделить preview и скопировать вручную.

## Экспорт

- Export workspace в боковой панели — полный JSON.
- Settings → Export JSON — такой же восстанавливаемый снимок.
- Settings → Export ZIP + Markdown — `workspace.json` и семь файлов каждого проекта; папки имеют безопасные имена и UUID.
- Снимок содержит проекты, задачи, память и текущий журнал, но не `.env`, credentials или npm-зависимости.
- Вручную записанные в Memory секреты, разумеется, попадут в экспорт — не храните их там.

Храните внешнюю резервную копию отдельно от папки приложения и самой БД.

## Импорт / восстановление

Settings → Import JSON backup. Из ZIP сначала извлеките `workspace.json`.

1. Проверяется размер, JSON, версия 2, UUID, длины, статусы, связи, DONE и циклы зависимостей.
2. Пользователь подтверждает полную замену workspace.
3. В одной транзакции текущий workspace копируется в backup-таблицу и заменяется новым.
4. При сбое предыдущая рабочая область не изменяется.
5. Download pre-restore backup скачивает последнее предыдущее состояние. Его можно снова импортировать.

API ограничивает запрос 3 MB; UI принимает JSON до 2.9 MB. Максимум: 200 проектов, 5000 задач, 1000 событий, 20 000 символов на файл памяти. Более крупные данные потребуют изменения лимитов и архитектурной проверки.

Автоматические предвосстановительные копии пока не очищаются; при частом восстановлении размер БД растёт. UI скачивает только самую последнюю копию. Это дополнительная страховка, а не замена внешнему backup.

**Совместимость с неизвестным JSON V1 не заявляется.** Для адаптера понадобятся схема/пример V1 без секретов. Несовместимый импорт отвергается, а не пытается угадать структуру.

## Обновление Project OS

1. Settings → Export JSON. Сохраните копию вне проекта.
2. Остановите сервер: Ctrl+C.
3. Получите проверенные изменения кода через Git / замену файлов, не удаляя `.env`.
4. Просмотрите изменения `src/db/schema.ts`. Для этой V2 используется Drizzle push, миграционная история ещё не создана.
5. Выполните `scripts\start-project-os.cmd --setup`.
6. Проверьте lint, typecheck, build; затем откройте Project OS.
7. Проверьте количество проектов/задач и откройте несколько Memory-файлов.
8. При необходимости восстановите JSON-экспорт, но только в совместимую версию приложения.

Перенос на другой компьютер: код + отдельный `.env` + установленный PostgreSQL + setup + импорт JSON. Копирование одной папки приложения не переносит данные PostgreSQL. Не переносите node_modules/.next между ОС.

## Типичные ошибки

| Ошибка | Что сделать |
| --- | --- |
| `node` не найден | Установить Node.js 22 LTS, затем заново открыть терминал/ярлык |
| DATABASE_URL is required | Создать и заполнить `.env`, проверить расширение файла |
| Cannot connect to PostgreSQL | Запустить службу, проверить имя БД, роль, пароль, порт и права |
| Schema missing / Workspace unavailable | Для отдельной V2 БД выполнить `--setup` или `npx drizzle-kit push` |
| Port is in use | Остановить только свой сервер или изменить PORT; не завершать случайные процессы |
| Build missing | Выполнить `--setup` или `npm run build` |
| Workspace changed in another tab | Сохранить свой черновик отдельно, обновить вкладку, повторить изменение |
| Confirm completion criterion | Заполнить критерий и подтвердить, что результат проверен |
| Complete dependencies first | Завершить зависимости или исправить ошибочную зависимость |
| Clipboard unavailable | Открыть localhost / выделить текст preview и скопировать вручную |
| Incompatible backup | Использовать V2 JSON; не переименовывать ZIP в JSON |
| Не открывается браузер | Вручную открыть адрес из launcher, обычно http://127.0.0.1:3000 |
| PowerShell запрещает скрипт | Создать ярлык через Проводник; не отключать политику безопасности |

## Безопасность и ограничения V2

- Это **локальное, доверенное, однопользовательское** приложение без авторизации. Не публикуйте его в интернете, не пробрасывайте порт, не используйте как общий сервер. Preview в среде разработки не является безопасным публичным production-развёртыванием.
- Launcher слушает только `127.0.0.1`; API запрещает браузерные cross-origin writes и принимает только JSON. Это не замена сетевой изоляции и авторизации.
- PostgreSQL credentials берутся из `.env`, не отправляются в UI и не входят в healthcheck.
- Нет обязательного AI API, агента, облачной синхронизации, автосинхронизации внешних Markdown, due dates или многопользовательского merge.
- В интерфейсе используется английский язык; полная русская локализация — отдельное улучшение.
- Реальная V1 и Windows-ПК не были доступны. Внедрение в существующий проект и Windows acceptance test остаются отдельными этапами.

## Windows acceptance checklist (выполнить на ПК пользователя)

- [ ] Чистая установка Node.js/PostgreSQL и `--setup` успешна.
- [ ] Путь проекта содержит пробелы; нет абсолютных путей в скриптах.
- [ ] Двойной клик ярлыка → проверки → готовый сервер → браузер.
- [ ] Повторный двойной клик не создаёт второй сервер.
- [ ] Отсутствие Node/.env/dependencies/schema диагностируется без секретов.
- [ ] Остановленный PostgreSQL приводит к понятной ошибке.
- [ ] Чужой процесс на порту не завершается.
- [ ] Создание проекта/задачи, Memory, Context, JSON/ZIP, восстановление работают.
- [ ] Закрытие браузера не удаляет данные и не останавливает сервер.
- [ ] Ctrl+C останавливает сервер; повторный запуск сохраняет данные.
- [ ] Перенос кода на другой ПК + setup + импорт восстанавливает workspace.

До выполнения этого списка Windows-launcher следует считать **реализованным, но не подтверждённым на Windows**.
