# Project OS V2 — состояние проверки

## Область проверки

Проверялся **этот репозиторий** в Linux-среде с локальным PostgreSQL, Node.js и Chromium. Это не проверка установленной у пользователя V1 и не Windows acceptance test.

## Подтверждено

- Next.js type generation, TypeScript `--noEmit`, production build и запуск с `/api/health`.
- ESLint без ошибок.
- `npm audit --omit=dev`: **0 уязвимостей** на момент проверки.
- Реальное соединение PostgreSQL и наличие схемы через `node scripts/launcher.mjs --check`.
- Четыре Playwright-теста:
  1. Overview, все разделы навигации, поиск, диалог и мобильная ширина 390 px без переполнения страницы.
  2. Создание проекта/задачи, сохранение после reload, подтверждение DONE, Memory, актуальный AI Context, реальное копирование в clipboard, JSON и содержимое ZIP.
  3. Сервер отклоняет DONE без подтверждения/критерия, несуществующий проект, цикл зависимостей и cross-origin write; устаревшая ревизия возвращает 409 без потери сохранённых данных.
  4. JSON-восстановление, сохранение после reload и точная копия прежнего workspace в предвосстановительном backup.
- Launcher в Linux на отдельном временном порту:
  - normal-mode достигает готовности;
  - повторный запуск переиспользует тот же экземпляр;
  - SIGTERM (эквивалент штатной остановки для этой проверки) закрывает сервер с кодом 0;
  - недоступная БД даёт понятное сообщение без пароля/URL.
- Git-репозиторий инициализирован; `.env`, зависимости, сборка и тестовые артефакты исключены. Commit не создавался от имени пользователя.

## Оставшиеся риски / gaps

### HIGH — до внедрения на Windows

Полный сценарий `.lnk → .cmd → Node → PostgreSQL → ready → browser` **не выполнен на Windows**. PowerShell COM shortcut, Windows PATH, права, service setup, повторный двойной клик и Ctrl+C должны быть проверены по acceptance checklist в README.

### HIGH — интеграция V1

Схема и JSON-формат реальной V1 неизвестны. Автоматическая совместимость и миграция не заявляются. Не применять эту схему к её БД без сравнения. Для следующего этапа достаточно конкретного файла схемы и обезличенного примера workspace/API V1.

### MEDIUM — dev-зависимости

Полный `npm audit` оставляет четыре MODERATE-записи в цепочке Drizzle Kit → @esbuild-kit → esbuild. В production-аудит они не входят. Рекомендация npm `--force` предлагает несовместимый откат Drizzle Kit на 0.18.1; он намеренно не применён. Не запускать Drizzle Studio/сборочные dev-серверы как публичный сервис. Обновить цепочку при наличии совместимого исправления, повторив проверки схемы и сборки.

### MEDIUM — область безопасности

Без авторизации приложение предназначено только для доверенной локальной машины. Launcher привязывает сервер к 127.0.0.1. Доступный в среде разработки preview не означает готовность к открытому интернет-развёртыванию.

### MEDIUM — резервные копии

История ограничена 1000 событиями. Автоматические предвосстановительные backup-записи пока не очищаются; UI скачивает последнюю. Нужны регулярные внешние JSON-копии.

## Повторение проверки

Из корня: `npm run lint`, `npx next typegen`, `npm run typecheck`, `npm run build`.

При работающем тестовом сервере: `npx playwright test`. Тесты с записью включаются только переменной `PROJECT_OS_TEST_WRITE=1` на одноразовом workspace. Команды для PowerShell и установка Chromium приведены в README.

**Итог:** работающая и проверенная реализация в этой среде; не окончательная сертификация локальной Windows-установки пользователя.
